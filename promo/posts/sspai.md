# 少数派 · 长文

标题：CCBar：把 AI CLI 的用量、积分和花费收进菜单栏

副标题：一个本地优先的多数据源用量面板

---

## 引言

同时使用 Claude Code、Codex、Trae 和 GLM 之后，一个问题会变得越来越具体：今天到底用了多少？

答案通常散在几个地方。cc-switch 有一套代理日志，ZCode 有自己的统计口径，Trae 的积分要打开网页看。它们各自都能回答一部分问题，但没有人把它们放在同一个视图里。

CCBar 是我为此写的一个 macOS 菜单栏应用，另外有一个 Windows 托盘版本。它不接管你的请求，也不上传数据，只做三件事：把多个来源的用量汇总起来，把历史和今天拼在一起，把结果放在抬眼就能看到的地方。

> 说明：本文作者是 CCBar 的开发者。文章会尽量把统计口径和限制写清楚，方便你判断它是否适合自己。

## 它解决的具体问题

第一个问题是「今天」和「历史」不在一个地方。很多工具能显示今天的 token，但一旦源数据库清理了旧记录，历史就断了。CCBar 的做法是：今天从源库实时读取，昨天及更早的数据每天补账进自己的 SQLite。源库始终只读，历史留在自己的统计库里。

第二个问题是口径。不同工具对 token 的定义不一样：有的把缓存读算进去，有的不算。CCBar 在界面上保留了各来源的口径差异，而不是强行抹平。比如 ZCode 采用 input + output，和它官方统计一致；Trae 的 input 本身包含缓存，入库时会折算成净输入，合计里不会重复计缓存。

第三个问题是积分。Trae 的积分和 token 是两套计量，普通用量面板很容易把它忽略。CCBar 单独做了积分页：今日积分、账户余额、按近 7 天日均消耗折算的可用天数，以及 7 / 30 天走势。

## 界面与功能

菜单栏是入口。开启后，标题栏直接显示今日 token 总量，按用量阈值变色，默认每 30 秒刷新。还有一个可选的像素小猫：没有用量时睡觉，用量越大跑得越快；不喜欢可以在设置里换回闪电图标。

点开菜单栏是今日面板：

- 今日卡片：请求数、缓存命中率、工时、积分
- 模型分布：按渠道分组的模型占比
- 趋势：昨日、近 7 天、近 30 天、历史总量
- 速率预测：按当前速度推算到 24:00 的用量

洞察中心是更完整的复盘界面，分为洞察、积分、流水、渠道、费用、分享和设置：

- 洞察：连续天数、周环比、90 天热力图、模型编年史、月度预测
- 积分：今日积分、余额与可用天数、7 / 30 / 90 天趋势
- 流水：任意日期逐笔回看，可按渠道和模型筛选
- 渠道：堆叠趋势、应用分布、Token 构成、缓存命中率
- 费用：走势、模型费用排行、性价比榜、月度预算进度
- 分享：周报卡和带二维码的今日战报卡，可保存或复制

此外还有一些偏「日常使用」的细节：六套内置主题和 JSON 主题包、中文 / English / 跟随系统、每日自动备份并保留 7 份、明细 CSV 幂等导入导出。CSV 导入按主键去重，重复导入不会产生新行，换机或多机合并时不容易重复或遗漏。

## 数据是怎么流动的

CCBar 的数据流可以概括成一句话：源库只读，历史本地化，今天实时拼接。

```
自建统计库（主连接）
 ├── usage_log   统一明细表（昨天及更早）
 ├── daily_agg   每日聚合缓存
 ├── meta        各源同步水位
 └── usage_all   视图 = 本地历史 + 各启用源「今日」实时数据
      ├── ATTACH ~/.cc-switch/cc-switch.db   （只读）
      ├── ATTACH ~/.zcode/cli/db/db.sqlite   （只读）
      └── Trae HTTP API（无本地库，直接写入 usage_log）
```

外部数据库通过 SQLite ATTACH 以只读方式打开，CCBar 不会修改它们。Trae 没有本地库，走官方 HTTP API 拉取会话用量与积分，凭据保存在本机，登录过期时会在界面上提示。

需要说明的是，Trae 的同步采用增量分页：以数据水位作为截止点，向前保留 30 分钟重叠窗口，遇到整页更旧的数据就提前停止。这样能减少重复请求，但意味着刚产生不久的数据可能晚一轮才出现。

## 安装与平台

macOS 版要求 macOS 13 及以上，提供 Universal DMG，拖进 Applications 即可。Windows 版是单文件 exe，运行后常驻系统托盘。

当前 macOS 安装包没有做 Apple 公证。首次打开如果提示「无法验证开发者」，可以右键应用选择「打开」，或者执行：

```
xattr -dr com.apple.quarantine /Applications/CCBar.app
```

这是目前最明显的安装摩擦，也是后续最想补上的一环。

## 已知限制

- 目前只支持 cc-switch、ZCode、Trae 三个来源，不是通用的 AI 用量面板
- 没有云同步，多设备需要手动导出 / 导入 CSV
- Windows 版功能与 macOS 版接近，但界面和部分洞察页仍在持续对齐
- Trae 的接口并非公开稳定 API，登录态或接口变化可能导致同步失败
- macOS 包未公证，首次启动需要手动放行

## 谁适合用

如果你只在用一个 AI CLI，系统自带的统计或服务商后台可能就够了。CCBar 更适合这样的场景：同时使用多个 CLI，希望在一个地方看到今天的总量和历史趋势；或者在用 Trae，想同时盯住 token 和积分余额。

项目是 MIT 开源的，源码在 GitHub。数据源适配器是按协议拆开的，接入新的来源不需要改查询和界面层。如果你正好有类似需求，欢迎试用后提 issue，尤其是统计口径和同步策略这两块。
