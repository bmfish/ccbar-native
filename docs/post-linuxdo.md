## 正文

最近算了一下账，被自己吓到了：**历史总量 99.5 亿 token**，光是今天 ZCode 就又干掉 2600 多万。

一直用 cc-switch 管 Claude Code 的代理和供应商切换，用量数据它都记着，但每次想看都得打开它的界面——而用量焦虑这东西，就是要"余光一扫就知道"才能治。于是写了个菜单栏小工具：**CCBar**。

【截图 1：菜单栏数字】

它干这几件事：

- **菜单栏常驻今日 token**，按用量分五档变色（绿 → 黄 → 橙 → 红），超了预警阈值直接弹系统通知
- **里程碑气泡**：每累计 N 万 token，菜单栏旁边蹦一个 🫧，配合"又烧了一个亿"的实感
- **弹窗面板**：今日请求数 / 缓存命中率 / 工时，模型分布（按数据源分组），昨日 / 近7天 / 近30天 / 历史总量
- **ZCode 也统计进来了**，而且按 ZCode 官方口径（input+output，缓存命中不计）——菜单栏数字和 ZCode 自己的用量页可以直接对账，GLM 套餐用户应该懂这个的意义
- 预警阈值、通知间隔、刷新频率、主题配色都可调

【截图 2：弹窗面板】

【截图 3：里程碑气泡】

技术上一句带过（详细见 README）：ccbar 自建了一个本地统计库，历史数据每天自动从 cc-switch / ZCode 的数据库**只读**同步进来，"今日"则实时查询——所以源库就算被清理，历史统计也不会丢，而且对源库零侵入。数据源是插件式的，实现一个三方法的协议就能接新工具，后面打算支持更多 agent。

Windows 版也有了（系统托盘，Python 写的），和 macOS 版同一套架构：

- macOS：https://github.com/bmfish/ccbar-native （Releases 里有 dmg）
- Windows：https://github.com/bmfish/ccbar-win

完全开源，纯本地运行，不上报任何数据。

用 Claude Code / ZCode 重度烧 token 的佬友可以试试，欢迎提 issue / PR——尤其是"还想统计哪个 agent"这种需求，说不定协议一实现就支持了。

## 跟帖备用回复

- **问：会不会和 cc-switch 冲突/改它的数据？**
  不会，全程只读 ATTACH，连写都不写它的库。历史统计存在 ccbar 自己的库里。

- **问：ZCode 的数字怎么和官方对得上？**
  专门按 ZCode 官方口径算的（input+output，缓存命中不计入），实测和它的用量页一致。

- **问：会统计 X 工具吗？**
  数据源是插件式的，只要那个工具把用量写在本地（sqlite/jsonl 都行），实现一个适配器就能接。欢迎在 issue 里提。
