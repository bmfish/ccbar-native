---

先说结论：看 Claude Code 用量的方式有四种，从官方到社区都有，但都有点"不顺手"。

**1. 官方 `/usage` 命令**

Claude Code 内置用量查询，缺点是只有订阅额度视角，且只在会话里能看到。

**2. ccusage（命令行）**

社区最流行，解析 `~/.claude/projects/` 下的会话记录，`npx ccusage` 就能出日报/周报：

```bash
npx ccusage@latest daily
```

缺点：每次要看都得主动跑一下，属于"回顾式"而非"监控式"。

**3. cc-switch 面板**

如果你用 cc-switch 管理供应商切换，它本身就记录了每次代理请求的明细，
打开面板能看。缺点同上：要打开它才能看。

**4. 官方 cost-tracker**

`~/.claude/cost-tracker.log` 记了成本流水，适合导出分析，不适合日常瞄一眼。

---

上面四种我都用遍了，共同的问题是：**都要"主动打开"才能看到**。而 token 烧起来的时候，你恰恰不想主动打开任何东西——等你想起来看的时候，额度已经没了。

所以我给自己写了个第五种：**CCBar，菜单栏常驻的用量计数器**。

- 今日 token 直接挂在 macOS 菜单栏上，余光一扫就有
- 按用量分五档变色，超阈值弹系统通知，每累计 N 万 token 弹里程碑气泡
- 数据源读的是 cc-switch 的本地库（只读，不改它的数据），ZCode 也接了，按 ZCode 官方口径统计、数字能直接对账
- 历史数据每天自动同步进自己的库，趋势图、按模型/按数据源分布都有

我自己跑了几个月，历史总量 9 亿+ token，今天又烧了小两千万——菜单栏看一眼就知道今天还能不能浪。

截图见回答配图（菜单栏 + 弹窗面板）。

**利益相关声明**：CCBar 是我自己写的，完全开源、纯本地运行、不上报数据，无任何付费环节：
- macOS：https://github.com/bmfish/ccbar-native
- Windows：https://github.com/bmfish/ccbar-win
